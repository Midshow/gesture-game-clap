# 合掌 QQ 联机对战引擎 · 交接文档（HANDOFF）

> 本包供接手开发者/AI 快速理解引擎全貌。含完整源代码、规则说明、接口文档与下一步路线图。
> 最后更新：2026-08-12 · 规则集 `base-online-v3`

## 1. 架构总览

```
QQ 玩家 ──私聊/群聊──> hezhang_gateway_qq.py（Python 网关，直连 QQ WebSocket）
                              │  解析 /命令，调用 HTTP
                              ▼
                  Node 裁判服务 src/server.mjs（127.0.0.1:3217）
                              │
                              ▼
                  src/rules.mjs（确定性规则引擎，无随机数争议：SHA-256 种子 RNG）
                  src/game.mjs（GameService：建房/加入/开局/出招/结算/删房/导出）
                  src/store.mjs（JsonStore：状态落盘 data/hezhang-state.json，临时文件替换写）
```

**设计铁律**：
- 网关只解析命令与转发消息；**一切房间状态与结算以 Node 服务为准**，不得在网关侧推测、补写状态。
- 规则引擎是确定性的：回合结算种子 = 玩家 id+行动+nonce 排序 + 房间号+回合+步骤，任何人可复算。
- 玩家身份用 QQ 平台稳定 openid（`user_openid`），昵称仅显示。

## 3. 规则引擎核心（rules.mjs）

### 行动表（MOVES）
| 键 | 名称 | 花费 | 类型/等级 |
|---|---|---|---|
| forge | 锻造 | 0 | 未被命中 +1 锻 |
| defend | 防 | 0 | 防 1-2 级 |
| catch | 接 | 0 | 防 2-3 级 |
| flash | 闪 | 2 | 防 2-5 级 |
| knife | 小刀 | 1 | 攻击 1 级 |
| scissors | 剪刀 | 1 | 特殊攻击 1.5 级（双人克制表） |
| katana | 武士刀 | 2 | 攻击 2 级 |
| shuriken | 手里剑 | 3 | 攻击 3 级 |
| kunai | 苦无 | 4 | 攻击 4 级 |
| dragon | 龙牙 | 5 | 攻击 5 级 |
| void | 虚无 | 6 | 攻击 6 级，全体目标 |

### 玩家四属性（2026-08-11 起）
- **HP**（初始生命，1-20）：≤0 死亡
- **攻击力**（0-10）：命中伤害 = 攻击者攻击力
- **锻数**（初始 0-10）：行动资源；重开清零（回 0，非回初始）
- **护盾**（初始 0-10）：每层挡一次任意大小非真实伤害

### 结算流程（resolveStep）
1. 全部存活者提交行动 → 支付花费 → 按等级从高到低逐级判刀
2. 3 级及以上同等级敌对攻击触发**抵刀**（全员免伤，不重开）
3. 攻击建立者拥有防御等级（本等级及以下不进入候选）
4. 命中判定：防/接/闪覆盖对应等级则防住；命中后先扣护盾（如有），否则扣攻击力点血
5. 锻造者被命中则不获得锻
6. 发生命中/接闪成功 → **重开**：存活者锻数清零、回合+1
7. 存活阵营 ≤1 → 对局结束（胜负/平局）

### 双人模式限制（base-online-v3）
- 仅 2 人、2 队各 1 人；第三人加入拒绝
- `mode` 仅支持 `duo`；`multi` 返回"多人模式暂未开放"
- 建房配置：`/创建 [HP 攻 锻 盾] [剪刀开|剪刀关]`，缺省 1 1 0 0、剪刀开
- 剪刀采用专门克制表，不按普通等级比较；房间关闭后服务端与QQ按钮同时禁用

## 4. HTTP 接口（除 /health 外需 `Authorization: Bearer <adminToken>`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查（无鉴权），含 ruleset 与房间数 |
| POST | `/rooms` | 建房 `{ownerId,ownerName,mode,hp,attack,energy,shield,scissors}` |
| POST | `/rooms/{id}/join` | 加入 `{userId,name,team}`（自动分空队由网关做） |
| POST | `/rooms/{id}/start` | 开局/重开 `{userId}`；finished 房重开恢复全员初始 |
| POST | `/rooms/{id}/view` | 玩家视图 `{userId}` |
| POST | `/rooms/{id}/submit` | 提交行动 `{userId,move,eventId}` |
| GET | `/rooms/{id}/recipients` | 仅供受信网关取得私聊收件人内部ID；不得转发给玩家 |
| DELETE | `/rooms/{id}` | 房主删大厅房，正文`{userId}`（仅 lobby） |
| GET | `/rooms/{id}/export` | 导出战斗记录（仅 finished） |
| GET | `/rooms` | 脱敏房间列表，供 `/房间` 搜索可加入房间 |

## 5. QQ 命令（全私聊，群内命令引导私聊）

```
/创建 [HP 攻 锻 盾] [剪刀开|剪刀关]   建房（缺省 1 1 0 0、剪刀开）
/加入 <房间号>         加入（网关自动分空队）
/开始 <房间号>         开局（全员广播）
/出招 <房间号> <招式>  秘密出招
/状态 <房间号>         查看房间
/记录 <房间号>         对局结束后导出战斗记录（分段私聊）
/房间                 搜索可加入的大厅房间
/删除 <房间号>         房主解散大厅房间
/规则                 帮助
```
招式别名：中文全名/简称 + 原有数字映射（0锻 1小刀 2武士刀 3手里剑 4苦无 5龙牙 6虚无 7防 8接 9闪）；剪刀使用中文或✂符号。
旧前缀 `/合掌 xxx` 兼容解析。

## 8. 部署与测试

```powershell
Copy-Item config.example.json config.json   # 替换 adminToken 为 64 位随机串
Copy-Item hezhang-gateway.example.json hezhang-gateway.json # 填写QQ凭据，admin_token与Node一致
npm start                                    # 或计划任务自启
npm test                                     # 运行全部回归测试
Invoke-RestMethod http://127.0.0.1:3217/health
python -m pip install -r requirements.txt
python hezhang_gateway_qq.py                 # QQ 网关（需 requests/websockets）
```

`npm test` 同时运行 Node 服务测试和 Python 网关纯逻辑测试。网关的完整 `/出招 房间号 招式` 按钮命令会先剥离房间号再解析招式；超时提醒仅在对手已经提交而本人仍待提交时发送。

**安全红线**：`config.json` 与 `hezhang-gateway.json`（含 QQ app_secret）不得提交公开仓库/外发；本包已脱敏。

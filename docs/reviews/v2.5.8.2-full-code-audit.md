# v2.5.8.2 全文件性能与冗余审查（2026-10-05）

本轮对象为当前单 HTML，包括内嵌 CSS、图片、规则数据、双人／多人引擎、AI、界面、存储和启动自检。旧版存档、根目录早期模块化实现及 Hermes 不在修改范围内。改动暂存本地，未升级版本或推送。

## 审查结论与修改

| 范围 | 发现 | 处理 |
| --- | --- | --- |
| 双人费用与合法招式 | 每次扫描38个角色，只有5个角色提供费用或招式修正；列举合法招式又为每招重复扫描 | 预先筛选5个规则键，保留原角色顺序；一次合法招式查询共用修正规则列表，查询结束即丢弃 |
| 被动技能分类 | 高频调用不断创建相同数组并线性查找 | 复用静态 Set；封锁与角色状态仍即时判断 |
| 双人 AI 历史权重 | 每个候选招式重复过滤同一段历史记录 | 每次权重计算只过滤一次；分数公式和候选顺序不变 |
| 多人 AI | 每招重新收集敌我、能量和威胁等级 | 一次同步决策内复用上下文，不跨出手缓存 |
| 技能目标选择 | 为取最高分，对所有目标排序 | 单次遍历选最高分；同分仍选原先第一个，随机抽取次数不变 |
| 双人战报 | 无尽模式每次刷新重建全部历史 DOM | 仅插入新增记录；重开、替换记录或回滚时重建；没有删减历史数量 |
| 战报图片 | 为取最近7条，先复制并逆序全部记录 | 先取7条再逆序，输出相同 |
| 历史残留 | 旧黑夜回溯、旧判刀选择等无调用函数；恒假技能分支；无人读取的开局／回合快照 | 删除已确认无入口的代码及无消费者的快照复制 |
| CSS、场景资源 | 约167KB的内嵌 WebP；规则文字也占用体积 | 原样保留图片和样式，SHA-256一致；保留完整规则正文和说明 |
| 结算、技能时机、随机、计时、存储、自检 | 分支多且存在行为依赖 | 保留规则与时序主体；不降低搜索深度、不修改AI权重、不压缩拍手等待、不更换存储格式 |

删除的函数包括：restoreSoloOpeningState、shuffledSkills、restoreMpSnapshot、restoreMpOpeningState、rollbackSuppressedMpAttack、attackCandidateTeams、applyJudgeDuelDamage，以及已无消费者的 snapshotMp、三个旧技能空／恒假占位函数。语法树与全文引用检查共同确认其入口情况。

这不是对全文件压缩或缩写变量名。文件仍可阅读和直接离线运行，未引入运行依赖。没有把双人和多人结算合并；其规则差异需要保留。

## 测量结果

基线是上一轮日志性能优化后的本地 v2.5.8.2，保存在 `output/performance/v2.5.8.2-audit-before.html`。本机桌面 Edge 无头浏览器，390×844 视口，未做手机CPU模拟。新旧版轮换先后顺序，14轮去掉4轮预热，报告10个样本的第75百分位。

| 指标 | 本轮修改前 | 本轮修改后 |
| --- | ---: | ---: |
| 文件字节数 | 515654 | 512596 |
| 双人地狱 AI 单次决策（通识者对囚徒，2锻对3锻） | 49.56ms | 15.14ms |
| 12人 AI 一轮选招（固定角色与5锻状态） | 0.268ms | 0.163ms |
| 双人500条战报的重复刷新（包括布局读取） | 28.6ms | 1.1ms |
| 页面 DOMContentLoaded | 70.4ms | 66.9ms |

文件净减少3058字节，约0.59%。AI与日志刷新收益明显；启动差异较小，不宣称获得稳定的启动提速。上述局部数据不能推算整局提速倍率。测量脚本保留原游戏难度与随机策略，没有通过减少思考深度获得这些数字。

## 行为验证

- 全部主游戏测试60项通过；新增组合费用顺序和技能封锁即时生效回归。
- 新旧构建对比2888种两角色技能组合／封锁配置下的费用和招式集合；对比38名角色与121种基本招式组合，共4598种战斗与伤害预览。
- 比较历史权重、六种代表角色在四档双人难度下的普通／技能模式决策，以及全部38角色的多人AI评分、目标和随机调用次数，结果一致。
- 两个构建分别执行完整第三版回归测试；规则、角色文字和默认数据一致。
- 两种视口下首页、设置、规则、双人界面共8组截图通过；模糊背景允许每颜色通道最多2/255的合成取整误差，本次最大1/255。
- 浏览器验证双人日志节点保留、插入顺序、HTML转义、回滚与清空；实际点击验证设置保存、暴君主动技能、多人成局、回合重开、淘汰后观战和移动布局，无浏览器异常。

测量／差分工具：`tools/benchmark-game-audit.cjs`、`tools/check-game-equivalence.cjs`。前者需要开发环境的Playwright与Edge，后者仅需Node。它们都接收修改前、后的HTML路径。测量结果在 `output/performance/full-audit-results.json`，本地生成物不属于运行依赖。

## 边界

未穷举所有角色获得多重技能后的无限状态空间，也未在真实低端手机上测量。双人日志增量路径依赖游戏现有的只追加、不原地编辑旧条目约定；后续若编辑旧战报，应更换日志数组以触发重建。多人上下文只在一次无异步等待的选招内有效，不能扩展为跨回合缓存。

这轮未调整AI对技能效果的预测模型、规则裁定或任何概率，也不声称修复尚未复现的帮闪问题。大型结算函数仍有拆分空间，但重构需要额外规则等价证据；仅为缩短函数而重排事件不在本轮范围内。

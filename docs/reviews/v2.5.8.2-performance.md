# v2.5.8.2 本地性能试验（2026-10-05）

本轮仅优化多人日志快照和界面刷新，未改规则、AI 策略、拍手等待或操作按钮逻辑，尚未提交发布。保留单文件离线运行。

## 改动

- 回滚快照仍深拷贝角色、技能、集合和当前结算上下文；历史日志采用列表浅拷贝。日志条目发布后不再修改，是这一优化的前提。后续功能若要编辑旧条目，必须创建新条目，不能原地改写正文或 trace。
- 可见日志依条目身份复用 DOM 节点，只创建新增行、删除离开最近150条范围的行，另保留一行折叠提示。判定说明展开状态得到保留，完整记录仍留在内存中。
- 角色区生成内容不变时跳过 innerHTML 替换；发生变化时仍完整刷新。操作按钮保持原逻辑。

## 测量

本机桌面 Edge 无头浏览器，390×844 视口（并非真机手机或 CPU 限速），12人。每个场景新旧版本交替先后执行24轮，丢弃4轮预热，取20个样本的第75百分位。日志含判定详情；每轮新增一条，所以记录数从初始量略有增长。渲染测量包含强制布局读取，不包含显示器实际绘制时间。

| 初始日志数 | 操作 | 原版毫秒 | 优化版毫秒 |
| --- | --- | --- | --- |
| 150 | 捕获快照 | 0.7 | 0.4 |
| 150 | 恢复快照 | 0.7 | 0.2 |
| 150 | 无变化刷新 | 12.5 | 1.1 |
| 150 | 新增一条日志后刷新 | 12.6 | 3.1 |
| 10000 | 捕获快照 | 23.7 | 0.3 |
| 10000 | 恢复快照 | 20.9 | 0.2 |
| 10000 | 无变化刷新 | 9.1 | 1.3 |
| 10000 | 新增一条日志后刷新 | 9.2 | 3.2 |

这是合成场景的局部耗时，不能解释为整个游戏按相同比例提速。微小毫秒差不设为 CI 硬阈值；以不重复创建相同日志节点、不深拷贝历史日志及规则结果一致作为稳定检查。

## 验证与复现

- 浏览器验证：刷新和新增记录后展开的详情仍保留；DOM最多150条日志加一条折叠提示；回滚恢复生命和日志；新旧版固定随机序列与时间戳下六次完整多人结算的角色状态、回合及日志完全一致。
- 主游戏回归增加快照隔离、重复恢复和历史记录不参与深拷贝检查。
- 本地基线：`output/performance/v2.5.8.2-before.html`。结果：`output/performance/multiplayer-results.json`。这些是本地测量产物。
- 使用 Node.js、Playwright 和 Edge 执行：`node tools/benchmark-multiplayer.cjs before.html after.html`。Playwright 通过环境中的 NODE_PATH 提供，仅开发测量需要，不进入游戏运行依赖。

未测真实手机、所有技能叠加或长时间内存曲线；本轮也不声称修复尚未复现的帮闪问题。

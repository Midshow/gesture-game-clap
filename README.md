# 合掌网页版

把面对面的“合掌”游戏做成一个可以直接分享、离线运行的网页游戏。

玩家可以与 AI 进行基础合掌或技能版对战，也可以在多人模式中和多名 AI 组队、混战。正式版本采用单 HTML 文件分发，不需要安装软件、注册账号或连接服务器。

## 游戏内容

### 双人对战

- 1 位玩家对战 AI。
- 支持标准、无尽等对局设置。
- 简单、普通、困难、地狱四档 AI 难度。
- 可自由开启或关闭技能。
- 可分别选择玩家和 AI 的角色技能。
- 支持可选的剪刀模式。
- 支持 0.5～15 秒的回合计时。
- 提供战斗记录、战绩统计和战报保存。

### 多人比赛

- 1 位真人玩家与多位 AI 共同参赛。
- 队伍数量支持 2～6 队，每队支持 1～4 人，总人数不超过 12 人。
- 根据队伍和人数自动形成单挑、组队、多队或混战局面。
- 可为玩家和每一位 AI 单独选择角色、随机角色或“无技能”；角色不可重复，“无技能”可重复选择。
- 多人普通攻击固定由所有合法敌对阵营共同进入判刀范围，不能指定目标队伍。
- 实现多人比赛中的判刀、抵刀、主动承伤、淘汰及 AI 自动续赛。
- 玩家被淘汰后，比赛仍会由存活 AI 继续结算至产生结果。

多人模式不启用剪刀。

## 规则提示

- 锻造用于积累能量，攻击会消耗相应能量。
- 攻击等级与消耗能量相关；同级攻击可能抵刀，高级攻击优先判定。
- “虚无”的 6 级表示攻击等级和能量消耗，并不表示造成 6 点伤害。实际伤害取决于角色攻击力。
- 多人比赛中，虚无按固定全体目标规则处理；极光则复制多把仍需分别随机判刀的攻击。
- 多人比赛中的接／闪可以在普通攻击命中对象确定前选择帮助：不帮时使用者本人安全，其余角色继续判刀；帮助时当前整把刀被防住、无人受伤并统一重开，但帮助者失去本次出手的自我保护。极光复制攻击没有帮接／帮闪窗口。
- 主动承受与帮接／帮闪是不同机制；主动承受者被选中后立即占用本回合一次判刀名额。
- 极光会复制出数量等于敌方人数的未定目标攻击，每一把都在命中前重新判刀。
- 游戏会区分“攻击打出”“攻击命中”和“实际造成伤害”。护盾、龙、秘偶、怪兽等效果可以防止伤害，但不会撤销已经发生的命中。

完整招式、技能说明及当前可用操作可以在游戏内的规则页面查看。技能规则以仓库中的原始规则文档和游戏内说明为准。

## AI

AI 会根据以下信息进行决策：

- 双方当前能量、生命和可用招式；
- 最近的出招记录与重复倾向；
- 攻防收益、风险和后续局面；
- 当前角色技能、主动技能次数和场上效果；
- 多人比赛中的阵营、目标、判刀和抵刀风险。

不同难度会采用不同的分析深度、风险偏好和应对强度。AI 仍包含一定随机性，因此相同局面不一定产生相同行动。

多人 AI 只根据公开状态和已揭晓的出招预测对手，区分普通随机判刀与虚无、极光的多目标风险，使用角色实际耗锻及攻击等级。即使地狱难度也保留混合选择，避免所有 AI 同步循环。帮助判刀发生在揭招后：AI 评估队友是否需要保护及自身承伤风险，不再固定概率替混战中的对手挡刀。

## 本地开发

如果需要查看早期模块化版本，可以在仓库根目录启动静态服务器：

```bash
python -m http.server 8080
```

然后访问：

```text
http://localhost:8080
```

全部主游戏规则测试可使用：

```bash
node --test tests/*.test.mjs
```

Hermes 联机服务源码位于 `hermes-hezhang/`，可在该目录运行 `npm test`。微信小程序及真人联机测试源码分别位于 `wechat-minigame/` 与 `online-server/`，使用方式见对应目录说明。

单 HTML 正式版可直接打开，不需要上述步骤。

## 反馈问题

如果发现规则或结算异常，请在 [Issues](https://github.com/Midshow/gesture-game-clap/issues) 中提交反馈，并尽量附上：

- 游戏版本；
- 双人或多人模式；
- 双方或各角色技能；
- 出问题前后的招式和能量；
- 战斗记录或截图；
- 预期结果与实际结果。

这些信息可以帮助快速复现判刀、技能优先级和 AI 决策问题。
